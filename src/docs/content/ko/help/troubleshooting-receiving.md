### 수신 탭 보기
콘솔 **로그 › 수신**의 **보낸 사람**에 보낸 주소를 **전체 그대로** 넣어 찾습니다(`name@example.com`처럼. 일부나 도메인만으로는 찾지 못합니다). 기록이 있고 결과가 보류라면 상세에서 사유를 봅니다. **수신 정책으로 보류**라면 아래 단계를 따릅니다. **인젝션 위험으로 보류**나 **검사 실패로 보류**는 수신 모드와 상관없습니다. [보류 사유별 할 일](/email/receiving#quarantine)을 보세요.

### 수신 모드 확인하기
에이전트 **이메일 › 수신** 열을 봅니다.
- **모두 막기**면 모든 메일이 보류됩니다.
- **허용 목록**이면 목록에 없는 발신자의 메일은 보류됩니다.
- **차단 목록**이면 목록에 있는 발신자의 메일이 보류됩니다.

### 목록 고치기
보낸 사람의 주소나 도메인을 허용 목록에 넣거나 차단 목록에서 뺍니다. **앞으로 오는 메일부터** 적용됩니다.

### 다시 보내 달라고 하기
수신 정책으로 이미 보류된 메일은 콘솔에서 풀어 에이전트에게 넘길 수 없습니다. 목록을 고친 뒤 보낸 쪽에 다시 보내 달라고 요청합니다.
:::

## 허용 목록에 넣었는데도 보류됨

수신 허용 목록은 발신 도메인 인증(DMARC)을 통과한 메일만 맞춰 봅니다. 보낸 쪽 도메인이 인증을 통과하지 못하면 목록에 있어도 보류됩니다. 보낸 쪽에 도메인 인증 설정을 확인해 달라고 요청하세요.

## 수신 탭에도 기록이 없음

- 보낸 사람이 주소를 정확히 적었는지 확인합니다. 대표 주소는 에이전트 목록에 보입니다.
- 보낸 쪽에서 반송 메시지를 받지 않았는지 물어봅니다.

## 인증 코드가 안 옴

[에이전트가 인증 코드 읽게 하기](/email/verification-codes)를 보세요. 사이트의 메일이 보류되지 않게 수신 모드를 먼저 확인합니다.

:::note 대부분의 에이전트에는 해당하지 않습니다
지금의 발신 모드 네 가지(전체·허용 목록·차단 목록·모두 막기)는 승인을 묻지 않습니다. 목록 밖 상대는 그냥 막힙니다. 콘솔로 만든 에이전트는 "전체", 조직 API로 만든 에이전트는 허용 목록 모드로 시작하고, 콘솔과 API에서는 예전 모드를 고를 수 없습니다. 그래서 승인 요청은 Atmark 운영자가 **예전 발신 모드**로 설정한 에이전트에게만 생깁니다. 이런 에이전트는 **이메일** 화면에 "예전 발신 모드입니다" 경고가 보입니다.
:::

:::tip 예전 모드를 그만 쓰려면
**이메일 › 발신**에서 네 모드 중 하나를 골라 저장합니다. 예전 모드는 한 번 바꾸면 다시 고를 수 없습니다.
:::

## 승인하기

승인은 콘솔이 아니라 **승인 요청 메일의 링크**에서 합니다. 메일은 주 소유자 주소로 갑니다.

:::steps
### 링크 열기
메일의 링크를 엽니다. 에이전트, 보내는 주소, 받는 사람, 메일 수, 승인 기한이 보입니다.

### 범위 고르기
**이 받는 사람만** 또는 **받는 사람의 도메인 전체** 중 하나를 고릅니다. 도메인 전체를 고르면 확인란을 체크해야 합니다.

### 승인 또는 거절
**승인**을 누르면 메일이 나가고, 앞으로 이 상대(또는 도메인)에게는 승인 없이 보낼 수 있습니다. **거절**을 누르면 메일은 나가지 않습니다.
:::

## 이런 화면이 보이면

| 화면 | 뜻 |
|---|---|
| 만료된 링크 | 승인 기한이 지나 발송되지 않았습니다. |
| 이미 처리됨 | 누군가 이미 승인하거나 거절했습니다. |
| 조직이 정지 중입니다 | 긴급 정지나 동결 중에는 승인할 수 없습니다. 정지를 푼 뒤 같은 링크로 다시 승인합니다. |
| 예전에 가입해 아직 운영자 검토 중인 조직입니다 | 검토가 끝난 뒤 같은 링크로 다시 승인합니다. |

## 에이전트 쪽에서 보이는 것

에이전트는 `pending_approval` 결과와 `approval_id`, 기한(`expires_at`)을 받습니다. 같은 메일을 다시 보내지 말고 `get_approval_status`로 결과를 확인하거나, 웹훅 `approval.resolved`·`approval.expired`를 기다립니다.
